# interrogate：兩個模型家族交叉審查

改編自 pstack `interrogate`。對抗的訊號來自**模型不同**，不是給同一個模型換角色扮演。交付物是一份判決，**不自動套用任何修改**。

## 1. 範圍

- 使用者指定檔案或 diff 就用那份。
- 程式改動：`git diff <base>...HEAD` 或 `git diff`（未 commit）。
- 文稿：文章檔與它的 ledger／brief。

## 2. 意圖

開審前，用一段話寫出這次改動想達成什麼（取自使用者訊息、commit 訊息、brief、程式碼）。拿不準就先問使用者。

## 3. 兩位審查者（互不知道對方的意見）

**審查者 A：目前的 agent 家族。** agent 支援委派時，派一個唯讀 subagent；不支援就自己做一輪，但要在看 B 的結果之前完成。

**審查者 B：codex（OpenAI 家族）。** 用本機 codex CLI 唯讀執行：

```powershell
codex exec --skip-git-repo-check -C "C:\Users\swank\Desktop\swanky.github.io" -s read-only `
  -c approval_policy=never `
  -o "<工作目錄>\interrogate-codex.txt" `
  "<審查提示詞>"
```

- `-s read-only`：codex 只能讀，不能改檔。
- codex 可以自己跑 `git diff`，提示詞裡給它 base ref 或檔案路徑即可，不必把整份 diff 塞進引數。
- 額度用盡（`You've hit your usage limit`）就停下，告訴使用者這次只有單一模型的審查，不要重試（見 `codex-image` 的額度說明）。

兩位審查者拿到同一份提示詞：

```text
你是嚴格的審查者。意圖：<第 2 步的段落>
範圍：<diff 指令或檔案清單>
請找出：正確性錯誤、會壞掉的邊界情況、與專案規範（AGENTS.md）的衝突、可維護性問題；文稿另查事實錯誤、說太滿、TA 看不懂的詞。
每條給：位置（file:line）、問題、為什麼重要、建議改法。沒有問題就說沒有，不要湊數。
```

## 4. 彙整

- 合併描述不同但其實是同一件事的意見，標出是哪個模型提的。
- **兩個模型各自獨立提出的，訊號最強**。只有一方提的照讀，但權重較低。
- 一方說有問題、另一方明確說沒問題的，記下分歧，當作判決的脈絡。

## 5. 主審判決

主審是務實的資深工程師，不是中立的轉述者。每條意見放進四級之一，附提出的模型與一句理由：

- **該改**：影響正確性、安全或可維護性的真問題，會擋下一個真實的 PR。
- **可考慮**：合理，但不確定現在處理值不值得。值得使用者看一眼。
- **知悉**：技術上成立但不必行動：看情況、太早最佳化、現階段影響小。
- **駁回**：錯誤、吹毛求疵或缺脈絡，附簡短理由。

## 輸出格式

```markdown
### 意圖
> <第 2 步的段落>

### 審查者
- A：<模型>，<N> 條
- B：codex <版本或模型>，<N> 條

### 該改
### 可考慮
### 知悉
### 駁回
### 一致與分歧
<兩個模型在哪裡一致、哪裡分歧，這個模式說明了什麼>
```

## Verification

兩位審查者的原始輸出都存在（A 的回報、B 的 `interrogate-codex.txt`），判決裡每一條都標出來源模型；若只有一位審查者完成，判決開頭明寫原因。
