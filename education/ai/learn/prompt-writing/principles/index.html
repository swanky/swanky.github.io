第二幕開場

還是那位聰明的新同事，只是這次要教他「為什麼」

〈AI 入門〉說過，Anthropic 官方指南建議把 AI 當成一位聰明、但剛到職的新同事：他做得出來，只是不知道這個團隊的慣例和做事方式（複習：{% include ai-learn/chref.html module=basics slug="prompt" anchor="prompt" label="交辦給第一天上班的新同事" %}）。

有意思的是，做 AI 的公司自己也照這個方向改。Anthropic 的 Claude Code 團隊分享過：他們把產品內建、使用者看不到的那段系統提示詞，砍掉了大約八成；「不要做什麼」寫少一點，改成多給任務脈絡，也就是為什麼要做、現在的限制是什麼。

這一幕的四個原則
  1. 規則要附理由
  2. 指示和資料分開放
  3. 先定義怎樣算完成
  4. 讓 AI 先反問你（追問的升級版）

只記一句新同事需要的是背景和理由，不是一長串禁令。

出處：Anthropic〈Prompting best practices〉；Simon Willison 記錄 Claude Code 團隊的分享 (2026-07-21)；站上導讀：Fable 田野指南。

原則 1：規則附理由

只給規則，AI 只改那一個字；附上理由，它會舉一反三

Anthropic 官方指南舉過一個例子：與其寫「絕對不要用刪節號」，不如寫「你的回答會交給語音朗讀引擎念出來，所以不要用刪節號，因為引擎不知道怎麼念它」。官方的說法是：AI 夠聰明，能從理由推到其他情況。

下面用一份公告示範（內容為虛構）：規則是「不要寫 ETA」。看 AI 是只避開那一個縮寫，還是連其他看不懂的縮寫也一起換掉。

可以直接抄「……，因為……」：每條規則後面，附一句理由。

只記一句多寫一句「因為……」，AI 就能自己判斷沒寫到的情況。

出處：Anthropic〈Prompting best practices〉Add context to improve performance；公告例為示意。

先看一例：拍影片的官方指南

一個鏡頭，只放一個運鏡、一個動作

進原則 2 之前，先看 OpenAI 給影片 AI「Sora 2」寫的官方提示指南。它說：動作往往是最難做對的部分，所以保持簡單。每個鏡頭只放一個明確的運鏡，加上主角一個明確的動作。

動作要拆成一拍一拍寫，例如「走四步到窗邊、停一下，最後一秒拉開窗簾」。片段也是越短越好控制：兩段 4 秒再剪在一起，常常比一段 8 秒穩。

全塞進一句（示意）

推軌、環繞、慢動作、轉身又奔跑，全寫在同一個鏡頭裡：AI 只好自己猜怎麼分。

拆開來交辦

一鏡一個運鏡、一個動作；兩人對話就拆成三個鏡頭，再剪起來。

寫信、做報表也一樣：背景資料、規則、這次要做的事，分開放。這就是原則 2。想看兩人對話怎麼拆鏡，站上有一篇完整圖解：先把鏡頭語言分成三層。

只記一句一次交辦一件事；不同層次的要求，拆開來各自交代。

出處：OpenAI〈Sora 2 Prompting Guide〉。

原則 2：指示和資料分開放

Prompt 三明治：資料框起來放上面，任務放最後

貼一大段會議紀錄或客戶來信給 AI 時，最怕它分不清哪些是「要它讀的資料」、哪些是「要它照做的指示」。做法有兩個：用成對的標籤把資料框起來，例如 <資料>……</資料>；再把這次要它做的事放在最後。這些符號直接打進對話框就好，AI 看得懂。

三家的官方建議，大方向一致、細節不同。誠實地列出來：

誰說的長文件放哪指示放哪
Anthropic放最上面問題放最後；官方內部測試，在複雜、多份文件的情況下，回答品質最多可提升約 30%。也建議用標籤把指示、背景、資料分開。
Google先放背景資料指示放在最後，並用清楚的分隔符號隔開。
OpenAI—建議在長文件的開頭和結尾各放一次指示；只放一處的話，放在資料上面效果較好。這和前兩家不同。

怎麼選？三家都同意「資料和指示要分開」。你常用哪家的 AI，就照那家的建議；不確定時，任務在最後再講一次，兩邊都顧到。

可以直接抄「<資料>……</資料>，請根據上面的資料……」：資料框起來，任務放最後。

只記一句貼長文件時：用標籤把資料框起來，任務寫在最後一段。

出處：Anthropic〈Prompting best practices〉Long context prompting、Use XML tags；OpenAI〈GPT-4.1 Prompting Guide〉；Google〈Prompt design strategies〉。

研究：台大李宏毅團隊（2025）

叫 AI「寫 N 個字」，它真的寫得剛好嗎？

進原則 3 之前，先猜一題。很多人交辦時最常寫的要求，就是「寫 300 字」。

小測驗 1／5：叫它寫 N 個字

研究者直接要求 GPT-4.1「嚴格符合指定長度」，它真的寫到指定長度的比例，大約是多少？

答案是 C：達標率不到 30%。模型常常寫太多或寫太少，因為它沒辦法可靠地在心裡數字數。
  • 研究者改用「邊寫邊倒數還剩幾個字」的提示，才把達標率拉到 95% 以上（英文測試）。
  • 另一份研究也發現：要求的長度一超過某個門檻，模型的表現就急速下滑。
  • 所以別考它數數：把要求寫成一眼能驗收的樣子，例如「3 段、每段 2 句」，交件後自己數一次。
看答案
C，不到三成；改成「3 段、每段 2 句」這種一眼能驗收的要求。

原則 3：先定義怎樣算完成

交辦時就寫好驗收條件，讓 AI 交件前自己對一遍

剛剛那題的教訓是：「寫 300 字」它做不準，但「3 段、每段 2 句」你一眼就能驗。把這個想法推廣到整份交辦，就是原則 3。Anthropic 的官方文件說得很直白：AI 覺得看起來做完了，就會停；沒有它能跑的檢查，你就成了驗收的人，每個錯都在等你發現。

完成條件怎麼轉起來

1交辦＋完成條件任務之外，寫下 3～5 條可以打勾的條件。
2AI 執行照交辦做出初稿，先不急著交出來。
3對照條件自查逐條標「通過／不通過」，附上依據。
4不通過就修改到全部通過才交；改不動的要說明。
範例：客戶延期通知信（示意）

寫完後用下面的條件逐項自我檢查，不通過就改到通過再給我：

不能打勾

「寫好一點」「專業一點」「簡潔有力」：每個人心裡的標準都不一樣。

可以打勾

「300 字以內」「第一段就說出新交期」：做到沒做到，一眼就知道。

先有標準，才有好 Prompt：Anthropic 的提示工程總覽也是這個順序：動手寫 Prompt 之前，先定好「怎樣算成功」，以及要怎麼測。站上專欄寫過《Clean Code》作者 Uncle Bob 的同一個心得：能讓機器檢查的，就交給檢查去擋。

可以直接抄「寫完後用下面的條件逐項檢查，不通過就改到通過再給我：……」

只記一句「好」要寫成可以打勾的條件，不要寫成形容詞。

出處：Anthropic〈Best practices for Claude Code〉；Anthropic〈Prompt engineering overview〉；延期通知信為示意。

原則 4：讓 AI 先反問你

三段可以直接抄的「先問我」Prompt

前三個原則都假設你知道自己要什麼。可是很多時候，連你自己都還沒想清楚。這時候別急著讓 AI 動手，先讓它把你腦袋裡的背景問出來。下面三段由淺到深，挑一段最接近你的情況：

① 先追問，不准動手（示意）我要替團隊做一份活動報名表單。請先追問目標對象、排除條件、要收哪些欄位、成功條件與個資風險，先不要開始做，因為範圍我還沒想清楚。每輪最多問 3 題。

② 指定它問的方向我要做〔功能〕。請詳細訪談我：問做法、畫面、邊界情況、疑慮與取捨；不問顯而易見的，挖我沒想到的難處。問完寫成一頁規格。

③ 非工程師版（示意）我想做年終聚餐的企劃。在你動手寫之前，請一題一題問我，直到我們對這件事有共同理解。每一題都附上你建議的答案，我同意就回「好」；每輪最多 3 題。

① 先別動手

明講「先不要開始做」，它才不會急著交一份猜出來的成品。

② 指定方向

告訴它先問哪些、別問哪些，問題才問在刀口上。

③ 附建議答案

每題附建議，你只要回「好」或改一句，省力很多。

設上限

不設限，它一次可能問出幾十題；先講好「每輪最多 3 到 5 題」。

可以直接抄「在你動手前，請一題一題問我，每題附上你建議的答案。」

只記一句不確定自己漏了什麼時，讓 AI 先把背景問出來。

出處：② 改寫自 Anthropic〈Best practices for Claude Code〉Let Claude interview you；①③ 為示意。

原則 4 延伸：追問的升級版

從「答不好再追問」，到「送出前就先做」

〈AI 入門〉：答不好再追問
  • 「照這個格式寫：……」
  • 「開始前先問我 3 個問題」
  • 「對照我的要求自我檢查」
  • 「第 2 段太長，濃縮成 3 行」

完整八招：{% include ai-learn/chref.html module=basics slug="prompt" anchor="tips" label="8 招讓 AI 更聽話" %}

這一幕：送出前，一次寫齊
  • 先訪問我：一題一題問到有共識，每題附建議答案（原則 4）。
  • 事先寫好完成條件（原則 3）。
  • 改兩次還不對：開新對話，把學到的寫進 Prompt 重來。舊對話裡堆滿失敗的嘗試，只會越修越亂。
  • 請 AI 幫你改 Prompt：「這段交辦還缺什麼？幫我改寫。」OpenAI 和 Anthropic 都有官方的 Prompt 改寫工具。

可以直接抄「這份交辦還缺什麼？請幫我改寫。」

只記一句與其每次答錯再追問，不如把追問的內容提前寫進 Prompt。

出處：Anthropic〈Best practices for Claude Code〉（讓 AI 訪問你、修正兩次不成就重開）；OpenAI〈Prompt optimizer〉；Anthropic〈Improve your prompts in the developer console〉(2024-10-14)。
