## 真正的差距，從來不在工具本身

在協助各種規模的團隊導入 AI 工具的過程中，我注意到一件很有意思的事：同樣付費使用 Claude Code，不同人的實際產出差距可以大到令人驚訝。

問題幾乎從不是「Claude 夠不夠強」，而是用法。

大多數人把 Claude Code 當成一個「比較聰明的補全工具」來用——輸入需求、等待輸出、再輸入下一個需求。這樣當然也能用，但遠遠低估了它作為**自主代理人（Autonomous Agent）**的真正潛力。

Claude Code 的更新節奏非常快，很多有意思的功能悄悄上線，連官方文件都還沒跟上。這篇文章整理的，是我在實際操作中真正改變工作流程的那些用法，不求全面，只求實用。

---

## 一、先把對話管好，才能把任務做好

AI 協作最常被忽略的隱性成本，是**對話的混亂**。一個被雜訊污染的上下文，會讓 Claude 逐漸跑偏，進而讓整個開發方向失焦。以下幾個工具，專門針對這個問題。

### 插話而不打斷：/btw

這是我近期最常推薦給協作者的指令之一。

場景是這樣的：Claude 正在執行一個耗時的大型任務，比如重構某個核心模組，這時你突然想確認一個不相關的小細節——「那個設定檔放在哪個目錄？」

過去的做法，不管你是直接插問還是等任務結束再問，都會在對話歷史裡留下一段跟主線毫無關係的問答，逐步稀釋 Claude 對當前任務的「焦點」。

`/btw` 解決的正是這個問題。它在主線任務之外開啟一個平行進程，你的問題得到解答後，這段對話可以直接抹除，主線絲毫不受影響。更重要的是，它複用當前的提示快取（Prompt Cache），**幾乎不額外消耗 Token**，是非常值得養成的操作習慣。

### 外科手術式回退：/rewind

許多人知道 Claude Code 可以雙擊 Esc 回退，但不知道這個動作在近期升級後，已經具備了細粒度的選擇能力。

執行 `/rewind` 後，你會看到一個選單，讓你決定回退的範圍：

| 選項 | 最適合的情境 |
|---|---|
| 同時回退代碼與對話 | 整個實驗方向都錯了，需要從某個節點完整重來 |
| 僅回退代碼，保留對話 | 代碼行不通，但 Claude 的分析過程有保留價值，換個方向繼續 |
| 僅回退對話，保留代碼 | 代碼是對的，但對話冗長已影響效能，清空討論釋放上下文 |
| 從此處壓縮對話 | 會話過長、Token 逼近上限，壓縮歷史以延續工作 |

這四種組合，對應著四種完全不同的開發現場。真正讓你大膽做實驗的，不是勇氣，而是知道自己永遠有退路。

### 認識自己的盲點：/insights

這個指令被嚴重低估。

執行後，Claude Code 會生成一份本地 HTML 報告，分析你過去一個月的使用模式——哪些指令你從未觸碰、哪些操作在重複浪費時間、哪些地方可以用自訂指令或 Skill 取代手工輸入。

換句話說，Claude 在**反向觀察你**。

建議每個月執行一次，把它當成自己的工作回顧。在高強度使用 Claude Code 的階段，人很容易形成路徑依賴，以為自己已經用得很熟練，但 `/insights` 常常會指出一些你根本沒意識到的冗餘習慣。

## 二、資源是有限的，智慧地分配它

Claude Code 的費用結構，決定了「如何使用模型」本身就是一個需要思考的問題。

### 規劃與執行分離：/model opusplan

這是一個不在預設選單裡的隱藏模式，直接輸入 `/model` 是看不到它的，必須完整鍵入 `/model opusplan`。

它啟動的是一種混合工作流：

- **規劃階段**：由 Claude Opus 4.6 主導，負責分析架構依賴、釐清技術決策、拆解複雜任務
- **執行階段**：自動切換至 Claude Sonnet 4.6，快速完成具體的代碼撰寫

這個設計背後的邏輯很清晰：**複雜推理與代碼生成，對模型能力的需求不同**。把最貴的算力集中在真正需要深度思考的環節，其餘交給效能更高的模型——對於 Pro 訂閱用戶來說，這是延長高階模型配額最直接的方式。

### 三個維度同時 Review：/simplify

每次與 Claude Code 完成幾輪密集的功能開發後，我習慣跑一次 `/simplify`。

它會並行啟動三個 Agent，分別從**代碼復用**、**代碼品質**、**運行效能**三個角度審查你的改動，最後彙整建議。AI 生成的代碼有一個規律性的問題：功能正確，但結構上常常夾帶冗餘——多餘的 import、相似邏輯的重複實作、可以更簡潔的寫法。這些不影響運作，但會慢慢侵蝕代碼庫的可維護性。

`/simplify` 做的事，相當於同時找了三位審查角度不同的資深工程師，在你提交之前幫你看一遍。

## 三、讓思路可以分叉，讓工作可以延續

好的開發工作流需要「可逆」，也需要「可記錄」。以下幾個指令處理的是這個面向。

### 平行宇宙的實驗場：/branch

如果說 `/rewind` 是後悔藥，那 `/branch`（原名 `/fork`）就是讓你在後悔之前就先佈局退路。

當 Claude 梳理完一個方案的脈絡，你想嘗試兩種完全不同的實現路徑，但又不想丟掉當前進度——分叉一個新會話，兩條路各自延伸，互不干擾，最後再比較結果。

這在技術選型或架構評估的場景裡特別有用。

### 決策是資產，不是過程：/export

一段深度的架構討論，往往比最終的代碼本身更有參考價值——它記錄了「為什麼這樣決定」，而不只是「決定了什麼」。

`/export` 將整段對話導出為 Markdown 文件。這份記錄可以作為未來補充上下文的素材，也可以直接傳遞給其他協作工具，讓不同的 AI 助理接棒繼續工作。

### 排程進行式：/loop

`/loop` 讓 Claude 定時重複執行特定任務。語法直覺：`/loop 5m 確認部署狀態` 代表每五分鐘執行一次，預設間隔是十分鐘。

結果會直接出現在對話上下文裡，Claude 可以基於這些結果進行判斷和後續操作，而不只是單純輸出狀態文字。值得注意的是，定期任務在建立三天後會自動到期——這是一個防止遺忘循環無限運行的設計。

## 四、打破空間限制，把工作帶著走

### 手機遙控本地環境：/remote-control

在終端機輸入 `/rc`，系統會產生一組加密 URL。用手機開啟，整個 Claude Code 工作環境就出現在你的手機螢幕上——雙向同步，兩端都可以操作，對話歷史完全一致。

關鍵在於：**代碼仍然在你的電腦本機執行**。手機扮演的角色只是遠端操作介面，你的檔案系統、MCP 服務、專案設定，全部留在本地，安全性不打折扣。

通勤途中審查 Claude 的輸出，或是在不方便打開電腦的場合繼續推進任務，都是真實的使用場景。

## 五、操作層的效率，從快捷鍵開始

最後整理幾個我每天都在用的快捷鍵，看似細節，實際上每次累積起來都是可感知的差距：

| 快捷鍵 | 用途 |
|---|---|
| `Ctrl+V` | 直接貼上截圖（Mac 同樣是 Ctrl，不是 Cmd）。Debug 時截圖貼入，Claude 直接看圖定位問題 |
| `Ctrl+J` 或 `Option+Enter` | 換行而不送出，撰寫多行 Prompt 的必備操作 |
| `Ctrl+R` | 搜尋過往輸入過的 Prompt，避免重複鍵入 |
| `Ctrl+U` | 清空當前輸入行 |

## 工具快，心態要更穩

Claude Code 的更新節奏相當驚人。很多功能在進入官方文件之前，早就悄悄部署進來了。

想跟上這個節奏，最直接的方式是定期翻閱 [CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)，以及關注開發團隊在社群平台上的動態——他們有時候隨口一提的新用法，比任何教程都快。

但比跟上更新更重要的，是建立自己的使用回顧習慣。`/insights` 是一個起點。工具進化得再快，真正決定生產力上限的，始終是**你如何組織自己的工作方式**。
