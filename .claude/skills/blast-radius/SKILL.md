# blast-radius：這個改動會弄壞哪裡

改編自 pstack `blast-radius`。列出誰引用了它不是重點，grep 一秒就有；重點是 **grep 找不到的波及**。

## 別信自己寫的分析

聽起來合理的波及分析，不論對錯都一樣有說服力。所以不要只交分析：找出整個改動「之所以安全」所依賴的一兩個事實，用執行去證明。

每個關鍵事實，標出它做到哪一級（越往下越可信）：

1. 我說的。單獨不算數。
2. 指出程式碼位置：真實的 `file:line`。
3. 推演壞情況走不到：一步一步走過失敗路徑。
4. 跑過了：一支腳本或測試呼叫真實程式碼，錯了會大聲失敗。
5. 在建置出來的站上重現過（用 `site-verify`）。

## 步驟

1. **讀改動**：diff、新增／修改／刪除的東西，以及它現在行為上的差別，包括 diff 沒寫明的部分。
2. **找出那一個關鍵事實**：多數看起來危險的改動，安全是因為某個單一事實（例如「這個 class 只有文章頁用」）。找到它，成立的話多數風險一次排除。時間花在這裡，不要列一長串「可能」。
3. **看 grep 停下的地方**（本站常見）：
   - Liquid：`{% include %}` 被哪些 layout 帶進來、include 參數、`page.xxx` 與 `site.data.xxx` 欄位被哪些頁讀；同一個 front matter 欄位名可能被別的 layout 用在不同意思。
   - 資料驅動頁：`_data/*.yml`、collection 欄位改名或改型別，所有讀它的頁面與 `tests/*.test.mjs` 都受影響。
   - CSS：class 名在 HTML、Liquid、JS 字串裡動態組出來（grep 不到完整 class）；選擇器權重改變會影響別頁；CSS 檔有版本號參數時要換號，不然瀏覽器吃舊檔。
   - JS：ES module 被哪些頁面以 `<script type="module">` 載入；Node 測試與瀏覽器載入路徑不同（見 `AGENTS.md` astronomy-engine 陷阱）。
   - 被排除或獨立的區域：`nft/` 是獨立子站；`_config.yml` 的 exclude；`llms.txt`、sitemap、RSS 是否列到這頁。
   - 圖片：同一張圖被 `-card.jpg`、`_data/oversized_images.json`、og image 引用。
4. **誠實評估每個風險**：給真實的發生機率與代價。確認存在的列「風險」，查過沒事的另列「已排除」。引用真實 `file:line`；搜尋沒結果也是答案，寫出搜了什麼。絕不編造呼叫者。
5. **證明那個關鍵事實**：寫一支小腳本或測試跑真實程式碼（或用 `site-verify` 在建置結果上驗），貼出執行結果。
6. **大改動要第二意見**：用 `interrogate` 請另一個模型家族再看一次。

## 交回什麼

- **它做了什麼**：改了什麼，包括不明顯的部分。
- **安全所依賴的關鍵事實**：寫出來、標出做到第幾級、附證明；證明不了就寫「未證明」。
- **風險**：怎麼壞、`file:line`、機率與代價、怎麼查。
- **已排除**：查過什麼、為什麼沒事。
- **上線前**：最便宜能抓到真 bug 的測試或重現步驟，含你寫的腳本。

## Verification

交回的內容裡，關鍵事實至少做到第 4 級並附執行輸出，或明寫「未證明」與原因。
