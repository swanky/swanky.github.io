When It Fits

真正的問題通常不在 prompt

企業導入 AI Coding 後，瓶頸常轉移到問題定義、背景資訊、審查、測試、權限與責任邊界。顧問工作從這些工程問題開始。

不知道從哪條工作流程開始

工具很多，卻不知道該先從需求、開發、測試、程式碼審查還是維運開始。

產出變快，品質卻不可預測

程式碼增加了，審查、回歸驗證與安全檢查沒有跟上，風險只是在後移。

每個人各用各的，無法複製

個人高手有成果，但團隊沒有共同背景資訊、操作規範、停止條件與驗收方式。

權限、資料與責任邊界不清

Agent 能讀什麼、改什麼、誰負責驗證，以及哪些資料不能進模型，都需要先定義。

AI Advisory FAQ

AI 導入常見問題

一定要使用 Claude Code 嗎？

不用。會依現有技術環境、權限、成本與流程評估 Claude Code、Codex 或其他工具；方法與品質邊界比品牌重要。

顧問會直接修改我們的程式碼嗎？

小範圍試行可在另行約定的範圍內檢視與協作，但由你的團隊操作自己的程式碼庫（repo）。服務重點是導入方法、審查與驗證，不是代寫功能。

完全沒有 AI Coding 經驗也能開始嗎？

可以。先用 Email 說明現況即可；後續通常從導入評估與非敏感範例開始，不必一開始就開放正式環境或大型程式碼庫。

可以只辦一場工作坊嗎？

若目標是學習工具或建立共同認知，較適合 Agentic Engineering 企業培訓；顧問工作坊則必須連到組織的實際決策或工作流程。

如何處理權限與機密？

Email 不收機密。進入試行前才另行約定 NDA、資料處理、可接觸範圍、工具權限與人工核准點。
